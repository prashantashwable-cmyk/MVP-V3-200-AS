## Real architectural finding (this phase's own audit, not previously documented)

`src/App.tsx` has **no `onAuthStateChanged` listener anywhere**. The only
real Firebase-Auth-backed login path (`handleGoogleSignIn`) calls
`signInWithPopup` once, then manages session state entirely with its own
`localStorage` token plus a lookup into the local `DbManager` user array —
it never re-verifies against the live Firebase Auth session on restore,
on refresh, or at any point after initial sign-in.

**Concrete consequence**: if a real user's Firebase Auth account were
later disabled or its refresh tokens revoked by an admin, this app's
locally-restored session would still present them as "logged in" until
they attempt an action that touches Firestore directly — where
`firestore.rules` would then deny the write. That IS a real enforcement
point, but an indirect, delayed one (a UI that still looks authenticated,
failing only on the next write) — not the direct client/backend identity
agreement this phase's brief explicitly asks to verify.

**Recommended real fix** (not implemented this phase — it is a genuine
behavior change to the login flow that needs to be built and verified
with a live project, not guessed at blind): wire a real
`onAuthStateChanged(auth, callback)` listener that re-validates the
Firebase Auth session on every app load and on every auth state change,
replacing (or running alongside, defensively, during a transition) the
current pure-`localStorage` restore path.

## Owner-bootstrap identity (found during this audit, not a bypass)

`src/lib/firestoreUsers.ts`'s `getOrCreateFirestoreUser()` auto-grants the
`admin` role, on FIRST real sign-in only, to one specific real email
address (the project owner's). This is a legitimate, common real-world
pattern for bootstrapping the first administrator of a fresh Firestore
project via a REAL, Google-verified identity — categorically different
from the Phase 32 demo bypasses (no password, code, or spoofable value
grants this; it requires actually controlling that real Google account).
Not flagged as a finding to fix, but recorded here for completeness since
Phase 31/33's brief is to inventory every environment-sensitive identity
grant.
