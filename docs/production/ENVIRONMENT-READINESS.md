## 2. Phase 32 fix summary (cross-referenced above, detailed here)

Full technical detail lives in `src/lib/demoCredentials.ts`'s own header
and `scripts/production-bundle-bypass-check.ts`'s header. Short version:

- **Root cause of the Phase 23 residual gap**: Phase 23 gated demo
  bypasses with a RUNTIME check (`if (!isProductionDeploy()) { ...
  '123456' ... }`). Vite's default esbuild minifier cannot prove that
  branch is dead at build time (it depends on a function call resolved
  only in the browser), so the literal strings stayed in the built
  bundle's TEXT even though non-functional in production.
- **The fix**: a real BUILD-TIME constant, `__DEMO_AUTH_ENABLED__`,
  injected by `vite.config.ts`'s `define` directly from
  `process.env.VITE_APP_ENV` — substituted as a literal `true`/`false`
  token before minification runs. Every bypass literal now lives inside
  `src/lib/demoCredentials.ts`'s own functions, each shaped `if
  (!__DEMO_AUTH_ENABLED__) return <safe-default>; return <demo-value>;`
  — a compile-time-constant branch the minifier's real dead-code
  elimination removes ENTIRELY, literal strings included.
- **Verified, not assumed**: `scripts/production-bundle-bypass-check.ts`
  runs a REAL `VITE_APP_ENV=production` build and a real default (demo)
  build, then greps the actual `.js` output files for every literal.
  Production: zero found. Demo: all found (a positive control proving
  the check can actually detect them, and that demo functionality
  genuinely remains available in an explicit demo build, not silently
  deleted everywhere).
- **Beyond Phase 23's original scope, found during this phase's audit**:
  `ForgotPasswordReset.tsx` had its OWN, separate, completely UNGATED
  universal password-reset bypass code (`'123456'` accepted for ANY
  account's reset regardless of environment) plus a "Developer Rapid
  Testing Sandbox" panel revealing the admin identity — neither was
  touched by Phase 23 (which only covered `src/App.tsx`'s own login
  form). Both fixed the same way. `ESignatureCapture.tsx` and
  `OfferOnboardingAgreementScreen.tsx` had non-differential simulated-OTP
  steps (any sufficiently-long input passes — not a real secret) also
  routed through the same module for consistency and honest production
  behavior (production now correctly rejects rather than silently
  accepting anything, since no real SMS/OTP backend exists in any
  environment).
