## Method

A live filesystem scan (not a stale snapshot) of every `.tsx` file in
`src/components/` (the 191-screen registry) for: (a) `DbManager.<method>()` call
sites, classified READ-shaped (get/list/fetch/find/query/search/select) or
WRITE-shaped (add/create/update/delete/remove/set/save/record/...) by name
pattern, and (b) a real import scan for the canonical repository/service modules
(`repository/entities`, `services/projectOperatingView`, `services/workQueue`,
`services/portalWorkSummary`, `services/controlTower`, `services/commercialWorkflow`,
`services/operationsWorkflow`, `services/legacyCommercialBridge`).

## What this measurement does NOT claim

This counts call SITES, not runtime read VOLUME — a screen with 3 read call sites
rendered on every keystroke may execute more real reads than one with 10 call sites
rendered once. It is a real, useful proxy for migration SCOPE (how much code touches
legacy data per screen), not a production read-volume/cost metric — no live traffic
exists in this sandbox to measure that directly.
