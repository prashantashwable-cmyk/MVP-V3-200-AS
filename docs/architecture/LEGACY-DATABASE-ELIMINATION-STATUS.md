## Removal plan (real, phased — no blind global rewrite)

1. **Do not** attempt a global find-and-replace of `DbManager` calls — this pack's
   own explicit rule, re-affirmed here. Every one of the 129 remaining components is
   a real, independently-tested, independently-rendered screen; a blind rewrite risks
   breaking all of them at once with no way to verify each one individually in this
   sandbox's time budget.
2. **Phase order, already proven safe by this pack's own experience** (Phases 15-18,
   45, 52, 54): (a) build a real dual-write bridge for a domain if none exists yet;
   (b) migrate that domain's READS to canonical, screen by screen, verified live
   (Phase 54's method); (c) once bridge-failure visibility is fixed (Phase 55's named
   gap) and reads are fully cut over for a domain, remove that domain's legacy WRITE.
3. **Priority order within that sequence**: the business-critical write list above,
   highest blast-radius first (payments/payouts/refunds, then contracts/PO/discounts,
   then credentials/permissions/roles), matching Phase 35's already-established P0
   ordering rather than inventing a new one.
4. **The 5 justified exceptions stay** (session bootstrap, language/theme prefs, one
   dev-only reset utility) — real, reasoned, not migration debt.
