## 2. A real correction to a stale Phase 01 finding

Phase 01's CSV flagged 5 components as "not referenced by name in any
router or `App.tsx`": `CameraCapture`, `CustomReportBuilder`,
`GeminiTools`, `LeadDetail`, `MapFiltersLayersControlPanel`. Live-checked
this phase across ALL of `src/` (not just router files, which was Phase
01's original, narrower scope): `CameraCapture` is actually imported by
`Dashboards.tsx`/`TechnicianOnboarding.tsx`/`SurveyorOnboarding.tsx`, and
`LeadDetail` is imported by `LeadKanban.tsx`/`LeadInbox.tsx` (and, since
Phase 15, is a real dual-write-bridged screen) — both were false
positives in the original, narrower scan. Only `CustomReportBuilder`,
`GeminiTools`, and `MapFiltersLayersControlPanel` remain genuinely
unreferenced anywhere — but none of the three use `DbManager` at all, so
none appear in THIS report's REMOVE category (which is scoped to
DbManager usage specifically, not a general dead-code report). This
correction is recorded here rather than silently repeating the stale
Phase 01 number.

## 3. The honest DEMO-ONLY negative finding

Zero files were classified DEMO-ONLY, explained directly in the
generated report: `DbManager` predates the Phase 04 demo/sandbox/
production environment model and is used IDENTICALLY regardless of
environment — there is no code path where a `DbManager` call is
exclusively reached in demo mode. The real demo/sandbox/production
distinction exists only in the Phase 04 repository layer this migration
moves usages onto. A screen only becomes genuinely "demo-only" (in the
sense the pack means) once it is fully `MIGRATED` — repository-backed,
with a real, separate demo/production split — not while it still reads/
writes through the one, environment-blind `DbManager`.
